# AI Hub (agentforce)

Package hub for AI coding tools: packages (skills, agents, MCP servers, tools, setup profiles) live in **git**; a FastAPI server
indexes them and serves a web UI + usage dashboard; a CLI (`aihub`, stdlib + kafka-python) installs and publishes them. Usage events go
through **Kafka**: each CLI produces them to one topic, the server consumes it and updates the database at once. Git carries packages, the
package index (written by the server in batches) and nothing else (no git inbox, no archive branch: Kafka carries every event, the database backup keeps them). Read this file instead of the whole repo; **update it in the same change** whenever you alter structure,
commands, behavior rules or gotchas below.

## Run and test

```sh
python -m aihub.server --host 127.0.0.1 --port 8000 --data /tmp/hubdata     # add --env-file/--ssl-cert/--ssl-key as needed
python -m unittest discover -s tests          # ~2.5 min, 230 tests; or name modules: python -m unittest tests.test_dev_workspace
```

- Use the venv python (`agent_store/.venv`), not system python. No pytest. `node` is broken on this machine: `app.js` cannot be syntax-checked, so re-read JS edits carefully.
- Test server: data `/tmp/hubdata`, login in `aihub-data/ADMIN_LOGIN.txt` (git-ignored). Stop it before restarting; stale `aihub.cli flush --background` workers pile up and can be `pkill`ed.
- `tests/__init__.py` clears `AIHUB_KAFKA_BOOTSTRAP` (defaults.json has none), so no test reaches a broker unless it sets one. Real-broker run: `AIHUB_TEST_KAFKA=localhost:9092 python -m unittest tests.test_kafka_e2e` (unique topic + group per run, topic deleted after).
- `__pycache__/*.pyc` are **tracked** in git, so every test run dirties the tree. Never `git stash` for comparisons (pop fails on pyc). Do not commit unless asked.

## Rules that are easy to break

- **CLI and `core/` stay stdlib-only** and Python 3.9 compatible. Server code needs 3.10+.
- **DB rows**: on Postgres a `Row` iterates its **keys**. Never `for a, b in cursor.fetchall()`; index by position (`row[0]`) or name. SQLite hides this bug, `test_backends` catches it.
- **All SQL goes through `Repos`** (`repos.py`); visibility is one function, `visible_sql`. New read paths must use it. New columns go in `db.py` `LATE_COLUMNS`.
- **Manifest metadata must never raise** (`authors`, display fields): a bad value is dropped, not an error, or installs and server sync break.
- Manifest fields: add to `manifest.normalize`, `docs/manifest.md`, `templates.HEAD`, and, if shown on the web, `pkgindex.add` -> `sync.py` -> `routers._ser` -> `app.js`.
- A CLI command change touches: handler + `add(...)`/`dev_commands` registration in `main.py`, `docs/cli.md`, `offline.md`, and the aihub-guide/aihub-package SKILL.md where relevant.
- Subparser wiring: `dev` commands run through `_each` (once per package) except `init/list/publish/tree/doctor/tree-solve`. `_each` uses `functools.wraps`; tests reach the raw handler via `.__wrapped__`.

## Feature notes

- **authors**: `[package] authors` (str or table list) -> normalized `[{name,email?,url?}]`. Flows manifest -> index entry -> version manifest -> `/packages/{name}` (`authors`, `license`) -> package page. `dev init` fills it from `identity.current()` (hub user, else OS user).
- **Top developers**: `Repos._top_developers` (shared by `/rankings/developers` and the dashboard `top_developers`, so they agree and honor dashboard filters). Credit = full package usage to each manifest author of the latest non-yanked version; no authors -> maintainers.
- **Monorepo (`aihub dev`)**: one `.git` in the parent, packages in sub folders, each with `aihub.toml`. `discover` finds them (a folder with a manifest is a leaf). `init --mono --packages a,b:mcp --remote URL`, `init --sub --name X`, `list`, `tree`, `doctor [--check] [--remote]` (sets `[git]` url/branch/subdir from the real repo), `tree-solve [--nested merge|keep]` (nested `.git`: merge moves it to `~/.aihub/backups`; keep adds `.git/info/exclude`). `publish`: prepares each package independently (auto `fix_git`, validate, commit), one push per repo, one failure never stops the rest, exit 1 if any failed. `init` refuses a package inside another or above existing ones.
- **OS / device**: CLI event field `os` (= `sys.platform`) -> `sync._os` (display name, e.g. macOS) -> `events.os` (`LATE_COLUMNS`). Filters `os` and `host` apply to `/dashboard`, `/dashboard/events` and `/audit` (+export); dashboard returns `by_os`, `by_os_daily`, `options.oses`; `/audit` returns `hosts`/`oses` for its dropdowns. Events synced before this change have `os` NULL.
- **Index bootstrap**: the server creates the index itself. `Sync.read_index`/`update_index` treat an empty repo, a missing index branch, or a branch without `index/root.json` as "create it" (empty `root.json`, pushed with `HEAD:refs/heads/<branch>`), then reset `sync_cursor` (now only a "an events pass completed" marker; empty = first run, which re-reads the index). `update_index` retries the whole batch (up to 3x, fresh fetch each time) when the push is rejected. CLI publish prints "publish event sent; the hub shows it now and adds it to the git index at its next sync", or a warning (Kafka not reachable; event queued) when both fail.
- **Usage events via Kafka**: `cli/telemetry.py` stamps every event with a unique `id`, spools it (O_APPEND), and a detached flusher (lock + heartbeat) waits `telemetry_interval` (env `AIHUB_TELEMETRY_INTERVAL` > config.json > `core/defaults.json` `telemetry.interval`, clamp 5..3600) so a burst is ONE batch, then `send()` produces each event as one message (kafka-python, `acks=all`, key = client id, topic `aihub.events`) and waits for the broker. Spool files are removed only after a successful send; a failure writes `queue/backoff.json` (30 s doubling to 15 min) and the events stay. Settings: `telemetry.kafka_config()` = env `AIHUB_KAFKA_<FIELD>` > config.json `kafka_<field>` > defaults.json `kafka`; no bootstrap server = nothing sent, spool kept. Fields: bootstrap, topic, security_protocol, sasl_mechanism, username, password, ssl_cafile. `/client-config` returns a `kafka` object with the first four only (never credentials) and `aihub setup` stores them. **Gotcha**: kafka-python 3.x raises `ValueError` for unknown config names (2.x did not), so the producer/consumer option names are checked by `test_kafka_index.RealClientLibrary` against the real classes; mocks cannot catch this. The zipapp builder copies `kafka/` into `aihub.pyz` (pure Python) so `install.sh` users need no pip; `pyproject` and `requirements-server.txt` list `kafka-python>=3.0`.
- **Server consumer**: `Sync.start` starts `kafka_in.KafkaIngest` (group `aihub-server`, manual commit, `auto_offset_reset=earliest`): poll -> `Sync.ingest(events)` (rows via `to_row`, untrusted; `ext_id` unique) -> commit. A database error means no commit, so Kafka redelivers. Messages > 64 KB or not JSON objects are dropped. The thread never dies (retry up to 60 s); state is in `sync.status["kafka"]` (Admin > Sync). Server settings: env > admin (`kafka_*` keys in `SYNC_KEYS`; `kafka_password` is a `SECRET_KEY`, shown as "set") > defaults.json.
- **Git index is written in batches**: `ingest_publishes` shows a publish event on the web at once (a provisional package/version row; an EXISTING package keeps its description/type/readme, an event only adds the version) and appends it to the persisted queue (`app_settings.index_queue`). A version already stored at the same commit is skipped with no git work. `run_once` (every `sync_interval`, the same Admin setting, default 60 s) calls `flush_index`: `update_index(queue)` = fetch each package repo at its commit, read its aihub.toml, ONE commit + ONE push; on failure the queue stays (and `run_once` reports it); a repo that cannot be read is retried up to `INDEX_TRIES` = 5 passes. After a flush `pull_index` re-reads those entries from git (their hashes are dropped) so the real manifest replaces the provisional one; `package_hide_missing` is given `names | queued_names()` so a queued package is never hidden for being absent from git. **The index remote is no longer polled** (`_index_moved` is gone): it is read on the first run, after a flush, or when `sync_index_dirty`. `POST /index/package` still forces one version.
- **`GET /api/v1/index`**: the CLI's index, built from the DB by `Repos.index_export(viewer)` (so it includes not-yet-committed versions; visibility and `public_browse` honoured), cached 1 h under `index:<scope>` (see Index cache), `ETag` = hash of the body, `304` on `If-None-Match`.
- **CLI index lookup** (`cli/registry.py`): `_hub_index` asks the hub first and caches `~/.aihub/index-hub.json` (`hub`, `at`, `etag`, `data`, `failed`); TTL `registry.ttl()` = `AIHUB_INDEX_TTL` > config `index_ttl` > `CHECK` = 300 s: inside it no request at all, after it ONE conditional request (304 keeps the cache). If the hub cannot be reached it falls back to the git index (same TTL: one `ls-remote`, fetch only when the branch moved) and leaves the hub alone for `HUB_RETRY` = 60 s. `AIHUB_INDEX_FROM=git` / config `index_from=git` skips the hub; a local file/dir `index_url` is always used as is; a cache from another hub URL is ignored.
- **No git inbox / archive**: `telemetry.deliver` (used by `dev publish` and `self-uninstall`) sends over Kafka; on failure the event is spooled and retried with backoff (publish included). `push_git`, `telemetry.source/target`, `Sync.pull_events/_archive/replay_archive`, `telemetry_*` admin settings and the legacy `telemetry/<client>` branches/refs are gone. Kafka credentials are OPTIONAL: a client with `AIHUB_KAFKA_USERNAME/PASSWORD/SASL_MECHANISM/SECURITY_PROTOCOL` (env or config) uses them as given (`kafkacfg.client_kwargs`), one without connects anonymously; the hub never sends credentials and the server schema/settings do not require them. Git logins are KEPT (publish and the git-index fallback need them): `remote_config.ensure_git_access` asks once when git refuses and stores the login through our helper (`cli/credhelper.py`: `aihub credential get|store|erase`; backends Keychain / DPAPI / `secret-tool` / 0600 `git-credentials.json`; `self-uninstall` calls `credhelper.unregister`). `Settings.load` expands `~`/`$VARS` in `data_dir`/`sqlite_path`. `gitx.BATCH` (set in `Sync.start`) gives network git a 300 s timeout and disables prompts.
- **Indirect install (`aihub install -i`)**: permission `indirect` (`db.ALL_PERMS`; default on for admin/publisher/user, never anonymous; `db.DEFAULT_ON` grants it once to existing roles at startup, recorded in `app_settings perm_default_<perm>`). `GET /packages/{n}/versions/{v}/bundle` (`routers._bundle_build`) gets a repo snapshot (`_repo_snapshot`: ONE git fetch per url+branch+commit, plain copy under `<data>/bundles/src`, so every package of a monorepo is served from it with no further git traffic), tars the package subfolder (no `.git`/symlinks) into `<data>/bundles`, cached per commit (branch tip 10 min), one lock per snapshot and per bundle; CLI `registry.checkout_via_hub` verifies `X-Bundle-Sha256` and extracts with `archive.safe_extract`. Tests: `tests/test_indirect.py`.
- **Index cache**: `GET /index` is cached under its own cache group `index:<scope>` (TTL 1 h, ETag/304). Only a package/version/visibility change drops it (`C(request).invalidate("index")` next to every `invalidate("pkg")` in routers; `Sync._drop_caches` for publish events and `pull_index`). Usage events drop `pkg` only, so they never make the server rebuild the index from the database. Keep new index-affecting writes calling `invalidate("index")`.
- **Events must not be lost**: CLI `enqueue` never drops (a spool over `MAX_SPOOL` is sealed into a `sending.*` file kept until Kafka accepts it); spool files are deleted only after a successful send. Server: `ingest_publishes` queues the version for the git index BEFORE `version_sync`, and only malformed events (ValueError/KeyError/TypeError) are skipped, so a database error propagates, `KafkaIngest` does not commit and Kafka redelivers (`ext_id` unique makes that harmless). Events carry both `user` (hub username, `~os-user` when anonymous) and `local_user`; `to_row` stores them as sent (`username` NULL when anonymous).
- **`aihub dev init` modes**: no flag + terminal + no `--name/--sub` -> `_init_mode` asks new / convert ONE folder / convert several. `--convert` (`_init_convert`) and `--convert-mono` (`_init_convert_mono`, checklist via `ui.select(multi=True)`, `--packages` names folders) both go through `_convert_one`: `convert.analyze` -> `_answer_questions` (asks ONLY for custom structure: unknown type, invalid name, competing scripts; no terminal or `-y` = ValueError naming the question) -> rename install scripts to the names `[scripts]` expects (`setup_mac.sh` -> `install-macos.sh`, ask first) -> `convert.build` -> lint. `--mono --packages` (empty new packages) is unchanged. `--type` default is None (detected when converting, else skill). Tests: `tests/test_convert.py`.
- **Usage hooks / counts**: Claude Code gets two hooks (`integrations.ClaudeCode.EVENTS`: `PreToolUse` for Skill/Task tool calls, `UserPromptSubmit` for a typed `/skill`); `hooks._skill_comp` matches names loosely (`/x`, `pkg:x`, case, `_`/`-`). Hooks are re-installed by every package install (`installer` -> `hooks.ensure`), so old installs migrate; `install_hook` adds only our entries to `settings.json` (nothing else touched, no write when already correct) and `hooks.verify()` runs after every CLI command (except hook/flush/hooks/uninstall) to restore a missing or outdated hook. Windows: `hooks._quote` writes forward-slash paths for Git Bash, `cmd_hook` reads stdin as UTF-8, every git child gets `gitx.popen_kw()` (CREATE_NO_WINDOW) and the flusher starts with CREATE_NO_WINDOW, not DETACHED (detached made each git flash its own console). Downloads shown on the package page, home (`overview`) and the `downloads` sort = legacy `versions.downloads` + COUNT of install/update events (`repos.DOWNLOADS_SQL`, `Repos.versions`; an event with an unknown version counts on the latest), so they agree with the dashboard/rankings and include events ingested before the change; never bump `versions.downloads` for events (double count); `Sync` drops the `pkg` cache after new events. `/activity` includes `publish` (with `version`).
- **Actor / localize**: `events.actor` (`LATE_COLUMNS`, set on insert by `repos.actor_key`: username else OS user, `~`, `(local)` and `@domain` stripped, lowercased; `backfill_actors` fills old rows at start). Admin setting `localize_users` (default 1, Settings > Sync) makes `Repos.actor_sql()` return `ACTOR_LOCAL` (the `actor` column) instead of `ACTOR`, so rankings, dashboard, audit filters and `_top_developers` (authors normalized too) merge one person. **CLI self events**: `main.record_cli_install` (once, `~/.aihub/.cli_installed`) sends `install` for package `aihub-cli` (`detail origin=web|git`); `self-uninstall` sends `uninstall` first; `dashboard_events` (the event list) shows package `aihub-cli` via `_dash_filter(with_cli=True)`; analytics (counts, charts, rankings) exclude it. `aihub logout` clears `credentials.json`.
- **`aihub self-uninstall [--yes]`**: removes packages, hooks, the `# >>> aihub` PATH block, `~/.aihub`. `aihub uninstall NAME` removes one package. `setup/welcome` has no sign-in menu, only a hint. Removal uses `gitx.rmtree` (read-only git objects); `gitx.fetch` wipes a cached checkout whose `.git` is damaged (`_sound`) and re-inits it, so a reinstall after a partial uninstall still reaches the index.

- **Anonymous permissions in the SPA**: `/meta` returns `anonymous_perms`; `app.js` `can()` falls back to them when signed out, so a `view_dashboard` grant on the `anonymous` role shows the Dashboard link/page without login.
