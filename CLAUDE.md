# AI Hub (agentforce)

Package hub for AI coding tools: packages (skills, agents, MCP servers, tools, setup profiles) live in **git**; a FastAPI server
indexes them and serves a web UI + usage dashboard; a stdlib-only CLI (`aihub`) installs and publishes them. Usage events go
through git too: each CLI adds a file to the single `telemetry-inbox` branch of an inbox repo, the server ingests it, archives it to `telemetry-archive` and removes it from the inbox. Read this file instead of the whole repo; **update it in the same change** whenever you alter structure,
commands, behavior rules or gotchas below.

## Map

| Path | What lives there |
| --- | --- |

| `aihub/server/` | `main.py` (app + install.sh/ps1 text), `routers.py` (all `/api/v1`), `repos.py` (all SQL, `Repos`), `db.py` (SQLite/Postgres layer, `LATE_COLUMNS`), `sync.py` (index -> DB), `static/app.js` (Preact+htm SPA, no build step; Admin tabs People / Roles / Sync / Backup / Settings), `static/style.css` |

## Run and test

```sh
python -m aihub.server --host 127.0.0.1 --port 8000 --data /tmp/hubdata     # add --env-file/--ssl-cert/--ssl-key as needed
python -m unittest discover -s tests          # ~2 min, 150 tests; or name modules: python -m unittest tests.test_dev_workspace
```

- Use the venv python (`agent_store/.venv`), not system python. No pytest. `node` is broken on this machine: `app.js` cannot be syntax-checked, so re-read JS edits carefully.
- Test server: data `/tmp/hubdata`, login in `aihub-data/ADMIN_LOGIN.txt` (git-ignored). Stop it before restarting; stale `aihub.cli flush --background` workers pile up and can be `pkill`ed.
- `tests/__init__.py` points `AIHUB_TELEMETRY_URL` at a path that cannot exist, so no test can push to the real hub repo (the bundled `defaults.json` names it; before this guard every run pushed fixture events there). A test that needs a real push sets its own temp bare repo, as `test_sync.Inbox` does.
- `__pycache__/*.pyc` are **tracked** in git, so every test run dirties the tree. Never `git stash` for comparisons (pop fails on pyc). Do not commit unless asked.

## Rules that are easy to break

- **CLI and `core/` stay stdlib-only** and Python 3.9 compatible. Server code needs 3.10+.
- **DB rows**: on Postgres a `Row` iterates its **keys**. Never `for a, b in cursor.fetchall()`; index by position (`row[0]`) or name. SQLite hides this bug, `test_backends` catches it.
- **All SQL goes through `Repos`** (`repos.py`); visibility is one function, `visible_sql`. New read paths must use it. New columns go in `db.py` `LATE_COLUMNS`.
- **Manifest metadata must never raise** (`authors`, display fields): a bad value is dropped, not an error, or installs and server sync break.
- Manifest fields: add to `manifest.normalize`, `docs/manifest.md`, `templates.HEAD`, and, if shown on the web, `pkgindex.add` -> `sync.py` -> `routers._ser` -> `app.js`.
- A CLI command change touches: handler + `add(...)`/`dev_commands` registration in `main.py`, `docs/cli.md`, `offline.md`, and the aihub-guide/aihub-package SKILL.md where relevant.
- Subparser wiring: `dev` commands run through `_each` (once per package) except `init/list/publish/tree/doctor/tree-solve`. `_each` uses `functools.wraps`; tests reach the raw handler via `.__wrapped__`.

## Feature notes

- **authors**: `[package] authors` (str or table list) -> normalized `[{name,email?,url?}]`. Flows manifest -> index entry -> version manifest -> `/packages/{name}` (`authors`, `license`) -> package page. `dev init` fills it from `identity.current()` (hub user, else OS user).
- **Top developers**: `Repos._top_developers` (shared by `/rankings/developers` and the dashboard `top_developers`, so they agree and honor dashboard filters). Credit = full package usage to each manifest author of the latest non-yanked version; no authors -> maintainers.
- **Monorepo (`aihub dev`)**: one `.git` in the parent, packages in sub folders, each with `aihub.toml`. `discover` finds them (a folder with a manifest is a leaf). `init --mono --packages a,b:mcp --remote URL`, `init --sub --name X`, `list`, `tree`, `doctor [--check] [--remote]` (sets `[git]` url/branch/subdir from the real repo), `tree-solve [--nested merge|keep]` (nested `.git`: merge moves it to `~/.aihub/backups`; keep adds `.git/info/exclude`). `publish`: prepares each package independently (auto `fix_git`, validate, commit), one push per repo, one failure never stops the rest, exit 1 if any failed. `init` refuses a package inside another or above existing ones.
- **OS / device**: CLI event field `os` (= `sys.platform`) -> `sync._os` (display name, e.g. macOS) -> `events.os` (`LATE_COLUMNS`). Filters `os` and `host` apply to `/dashboard`, `/dashboard/events` and `/audit` (+export); dashboard returns `by_os`, `by_os_daily`, `options.oses`; `/audit` returns `hosts`/`oses` for its dropdowns. Events synced before this change have `os` NULL.
- **Index bootstrap**: the server creates the index itself. `Sync.read_index`/`update_index` treat an empty repo, a missing index branch, or a branch without `index/root.json` as "create it" (empty `root.json`, pushed with `HEAD:refs/heads/<branch>`), then reset `sync_cursor` (now only a "an events pass completed" marker; empty = first run, which re-reads the index). A failed index update leaves the inbox files in place, so the next pass retries it. `update_index` retries the whole batch (up to 3x, fresh fetch each time) when the push is rejected. CLI publish prints "event sent; the hub will add it shortly", or a warning (package not in the index yet, event queued) when the telemetry inbox push fails.
- **Telemetry via git**: `cli/telemetry.py` stamps every event with a unique `id`, spools it (O_APPEND), and a detached flusher (lock + heartbeat) waits `telemetry_interval` (env `AIHUB_TELEMETRY_INTERVAL` > config.json > `core/defaults.json` `telemetry.interval`, default 15 s, clamp 5..3600) so a burst is ONE batch. `push()` adds one file, `inbox/<client_id>-<unix>-<rand>.jsonl`, as a commit on the tip of the single inbox branch (`telemetry-inbox`; depth-1 fetch; git plumbing in `~/.aihub/queue/git`). A non-fast-forward race refetches the tip and retries (`PUSH_TRIES` = 12, full-jitter backoff capped at 8 s; 40 clients pushing in the same second all land within ~30 s); each client has its own file, so there is never a content conflict. Users need write access to `telemetry-inbox` only, not `main`. Each push outcome goes to `queue/status.json` (shown by `flush -v`, `doctor`). Nothing is pushed when nothing is spooled; spool files are removed only after a successful push. The flusher is event driven (`record()` -> `kick()`), releases the lock before re-checking the spool, and runs another pass only if the last one sent events (max `MAX_PASSES` = 20). After a failed push `_fail()` writes `queue/backoff.json` (no flusher for 30 s, doubling to 15 min; `BACKOFF_BASE`/`BACKOFF_MAX`); a successful push or `aihub flush` clears or ignores it. `deliver()` (used by `dev publish`) pushes one event immediately and spools on failure. `telemetry.source()` resolves url and inbox branch: env `AIHUB_TELEMETRY_URL`/`AIHUB_TELEMETRY_INBOX_BRANCH` > config.json `telemetry_url`/`telemetry_inbox_branch` > bundled `core/defaults.json` `telemetry.git_url`/`inbox_branch` > index repo (url only). `telemetry_branch` (archive) is server-only. Server `Sync._collect`: `inbox/*.jsonl` on the inbox tip, plus legacy `telemetry/<client>/<batch>` branches and `refs/telemetry/*`, fetched into private `refs/inbox/*` (up to 500 per pass; files >5 MB or bad lines dropped). Git cost: one `ls-remote` per pass decides what to fetch (idle inbox = no fetch, no gc); blobs are read via `gitx.objects`/`gitx.blobs` (`cat-file --batch`), `_archive` builds its commit with plumbing on a depth-1 `refs/inbox/archive` (no worktree), `gitx.fetch_tip` fetches a branch tip without a prior `ls-remote` (CLI `push` uses it too). `pull_events` returns True also when a retried batch (rows already stored) updated the index. The server sets `gitx.BATCH` in `Sync.start`: network git commands get a timeout (300 s), credential prompts are disabled (GCM/askpass/ssh BatchMode) and stalled https aborts, because a git call waiting on a prompt used to freeze the single sync thread silently (no events, no archive, no index refresh). `Settings.load` expands `~`/`$VARS` in `data_dir`/`sqlite_path` and makes them absolute (a literal `~/.aihub/data` from .env made git fail on `.archive/0.jsonl`, so nothing was archived or trimmed); a pre-existing literal `./~/...` folder is kept with a warning so the old database is not orphaned. `Sync.start` logs the inbox/index locations; each pass with batches logs counts; `_index_moved` (one `ls-remote`) re-reads the index when its branch moved, not only after a publish event. `pull_events` stores rows (`to_row`: untrusted, redacted, `ext_id` = event id, unique), `_archive` writes `archive/<day>/<client>-<unix>-<rand>.jsonl` on the archive branch (admin `telemetry_archive=0` disables), and only then `_remove` deletes exactly those inbox files (one commit via `_trim_inbox`), the legacy branches/refs, and gc. Any failure keeps them for the next pass. The server's git account must push both branches and delete legacy `telemetry/*`. Server settings: env > admin (`telemetry_url`, `telemetry_inbox_branch`, `telemetry_branch`, `telemetry_archive`) > defaults.json > index repo; the inbox branch is not an admin field (env, config or defaults only). `run_once` runs the inbox and index halves independently; any failure goes to `status.last_error` (plus `events_error`, `index_error`, `archive_error`) and the cursor advances only on a clean pass. `/client-config` returns locations only (`index`, `telemetry`, `refresh_hours`), never credentials. `aihub dev stats` reads the hub `GET /packages/{name}/stats`. Recovery: `Sync._needs_replay` (no events in the table, or cursor cleared by a forced full sync) -> `replay_archive()` re-inserts everything on the archive branch before the refs are pulled; a missing archive branch is created by the first `_archive`; `_clear_worktree` removes any leftover `.archive` scratch folder (now only temp files for `hash-object`) before and after; it runs no git process when nothing is left. `remote_config.resolve_missing` is silent (env > config > defaults.json); only `ensure_git_access` ever prompts, and only for git credentials.
- **Usage hooks / counts**: Claude Code gets two hooks (`integrations.ClaudeCode.EVENTS`: `PreToolUse` for Skill/Task tool calls, `UserPromptSubmit` for a typed `/skill`); `hooks._skill_comp` matches names loosely (`/x`, `pkg:x`, case, `_`/`-`). Hooks are re-installed by every package install (`installer` -> `hooks.ensure`), so old installs migrate; `install_hook` adds only our entries to `settings.json` (nothing else touched, no write when already correct) and `hooks.verify()` runs after every CLI command (except hook/flush/hooks/uninstall) to restore a missing or outdated hook. Windows: `hooks._quote` writes forward-slash paths for Git Bash, `cmd_hook` reads stdin as UTF-8, every git child gets `gitx.popen_kw()` (CREATE_NO_WINDOW) and the flusher starts with CREATE_NO_WINDOW, not DETACHED (detached made each git flash its own console). Downloads shown on the package page, home (`overview`) and the `downloads` sort = legacy `versions.downloads` + COUNT of install/update events (`repos.DOWNLOADS_SQL`, `Repos.versions`; an event with an unknown version counts on the latest), so they agree with the dashboard/rankings and include events ingested before the change; never bump `versions.downloads` for events (double count); `Sync` drops the `pkg` cache after new events. `/activity` includes `publish` (with `version`). CLI index: `registry.CHECK` = 20 s, then one `ls-remote`; fetch only when the branch moved. Admin > Sync shows archive status (`archive_last`, `archive_files`, `archive_commit`).
- **`aihub self-uninstall [--yes]`**: removes packages, hooks, the `# >>> aihub` PATH block, `~/.aihub`. `aihub uninstall NAME` removes one package. `setup/welcome` has no sign-in menu, only a hint.
