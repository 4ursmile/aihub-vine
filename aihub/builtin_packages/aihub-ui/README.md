# aihub-ui

A local, Claude-style chat and control UI for AI Hub.

```sh
aihub install aihub-ui
aihub run aihub-ui          # background service; the address (with this session's key) is in ~/.aihub/ui/url.txt
```

- **Chat** with the Claude Code harness (`claude -p`): model, effort and mode pickers, attachments, history in folders. Models, login, hooks, MCP servers, skills and agents all come from Claude's own `settings.json`, so everything `aihub install` registered is usable.
- **Answers render in place**: shell sessions, code, sortable tables, charts (`chart` blocks) and forms (`form` blocks, the submit goes back as your next message). Claude is told about them in the chat's frozen system prompt.
- **Context window**: a ring shows usage against the size set in Settings (default 1M tokens; also sent to Claude Code as `CLAUDE_CODE_AUTO_COMPACT_WINDOW`); Compact now, auto-compact and its limit. `/` opens slash commands: the UI's own, Claude Code's, and `slash/*.slash.json` from packages.
- **Live work card**: while Claude works you see the phase (reasoning / tools / answer), a step list with each tool and its result, the reasoning as it streams, counters (time, steps, estimated tokens, context) and two buttons: **Stop** and **Answer now** (stops the tools and asks for a short direct answer in the same session). Finished reasoning is a collapsible block.
- **Talk while it works** (Claude Code mode): a message typed during an answer goes straight into that answer; Claude reads it at its next step (after the current tool call), like typing into Claude Code while it works. It waits as a dashed chip until Claude has read it, then shows in the chat tagged "sent while Claude was working". **`/btw <question>`** asks a quick side question (also mid-answer): a throwaway fork of the chat answers it from the conversation in one step without tools; the answer is a dismissible card above the box and is not added to the chat. Free chat queues the message for when the answer ends.
- **Free chat**: the engine pill in the composer switches a chat to the UI's own harness: one streaming call to the Messages API, no Claude Code, no tools or files, fast and cheap. It needs `ANTHROPIC_API_KEY` (Settings > Encrypted secrets, or the `env` block / `apiKeyHelper` of your Claude settings; `ANTHROPIC_BASE_URL` is honoured; a subscription login only works through Claude Code). Switch at any message; earlier text carries over, tool calls do not. Free chat can use MCP servers: tick the ones you want in the engine pill (servers of installed aihub packages, the MCP servers page, and Claude Code's user servers; stdio only). The model then calls their tools in a loop (up to 12 rounds per message) and the calls show in the live card like Claude Code's. It draws an svg or writes an html report to the canvas only when you ask for one.
- **AIHubness** (engine pill, or `/engine aihub`): the UI's mini agent between Free chat and Claude Code. Same API key as Free chat, but with tools on the chat's working folder: `read`, `ls`, `grep`, `edit`, `write`, `run`, `digest`, `memory`. It loops (up to 40 rounds), retries failed steps and busy API calls, and keeps its own memory notes across chats (`~/.aihub/ui/harness/memory.md`). It is built for few tokens: about 1.7k tokens of fixed prompt (Claude Code: about 40k), a moving prompt-cache breakpoint, big files cut to their first lines plus an outline, unchanged re-reads skipped, long command output folded to head and tail with the full text saved for `grep` / `digest`, `digest` to send a big file to a small model with a question, old tool output trimmed in long tasks, and later messages get earlier ones as text plus a one-line list of steps. Commands ask like Claude Code: a card in the chat shows the command with Allow once / Always allow `<prefix>` (for this chat) / Deny, and the task waits (Stop ends it; no answer in 15 minutes = denied). Read-only commands (`ls`, `cat`, `rg`, `git status/diff/log`...) run without asking; Auto also runs test, build and lint commands, Accept edits asks for them; file edits in the working folder run. Deletes and discards (`rm`, `git clean`, `find -delete`, `git reset --hard`, removing a memory note...) and risky commands (`sudo`, `git push`, `kill`, `curl | sh`, publish) ask every time, never covered by Always allow. Bypass asks nothing. Plan / Read only = look only. Unattended Works runs refuse what would ask. Manage the memory notes (view, edit, add, delete) under Knowledge > AIHubness memory. Handoff chain: Free chat hands a task that needs files to AIHubness (on by default), and AIHubness hands one it cannot do to Claude Code (off by default). Both switches are in the engine pill and under Settings.
- **Working folder**: each chat works in `~/.aihub/workingspace/sessions/<id>` unless you pick a folder (folder chip in the chat header; a missing folder is created, the chat moves into a sidebar project of the same name, and new chats started in that project reuse it). Changing it starts a new Claude session that carries the conversation as text. **Soul**: the person button gives one chat its own soul text (or back to your soul note). **Search chats** in the sidebar looks in titles and messages.
- **Canvas**: a file tree of the working folder, live; Preview (Markdown files render like a chat answer: tables, code, charts, relative images), **Edit** (Ctrl/Cmd+S saves) and **Diff** (since your last message, or since the last git commit) tabs, and a split mode that shows the preview beside the editor or diff; `.html` files get a sandboxed live preview; Jupyter `.ipynb` notebooks open as cells you edit in place (add, move, retype, delete, clear outputs; Save writes the notebook, there is no kernel); `.drawio` files are drawn by draw.io's own viewer (loaded from www.draw.io, or from `ui/static/vendor/lazy/drawio/viewer-static.min.js` when you put it there for offline use), and by the built-in renderer when it cannot load; **VS Code** and **Open folder** (Finder / Explorer) buttons open the working folder or the selected file; `html`, `svg` and `openui` code blocks render under Elements. Components are [OpenUI](https://openui.com) (`@openuidev/react-lang` + `react-ui`), taught to Claude through the chat's frozen system prompt.
- **Packages**: installed list, find, install (options default on, then a settings form for keys), update, enable/disable, uninstall.
- **Services**, **MCP servers**, **Knowledge** (soul and notes = memory), **Works**: node graphs that start on a cron schedule, a webhook, a click or a package's own event source, with regex filters, Claude tasks (choose model / effort / mode) and package nodes. Mail: **Send email (SMTP)** (any server, any system; send, draft into the account's IMAP Drafts folder, or a `.eml` file) next to the Outlook package node (`aihub-nodes-outlook`, Windows; send, draft, display). **Saved nodes** (Works > Saved nodes): set a node up once, logins included (encrypted), then add it to any work from Add node > Saved nodes; empty fields follow it, typed ones change that work only. Data: **SQL database** (SQLAlchemy: PostgreSQL, SQL Server, Oracle, Trino, MySQL, SQLite, DuckDB; native, pandas or polars; writes tables), **Trino SQL** and **Spark job** nodes; node code reads the logins and S3 buckets it is granted through `aihub_vault`, databases through `aihub_data`. Code nodes have an **Environment** box (their Python, what is missing, one-click install or the one command), **Magic ask** (describe it, a model fills in the fields and code; Apply to keep) and a colour code editor that expands full screen to **Run** the node and preview its result. Headless runs: see "Works without the UI" below. Guide: `docs/ui-nodes.md`.
- **Settings** also holds the Vault (git logins), the hub sign-in (highlighted while you are signed out) and the context window.
- Same state as the terminal: it calls `aihub --json ...`, so login, vault and packages are shared.

## Works without the UI

`aihub work` runs the same Works as this page from a terminal or a server, with no browser. It reads the same files, so a work designed here runs there, and the other way round. It needs this package (`aihub work` offers to install it). Every command is in `docs/cli.md`.

To run a shared workflow on a server:

1. `aihub install aihub-ui`.
2. `aihub work pull workflow-sales-etl` adds its works, switched off.
3. `aihub work setup sales-etl --creds creds.json --env data` sets its credential sets, folders and secret fields (or answer the prompts; `aihub work cred template s3` prints a skeleton), then installs the Python packages its SQL / Spark / Python nodes need into the environment `data`. Later or on its own: `aihub work env install sales-etl` (`aihub work env check sales-etl` lists them).
4. `aihub work run sales-etl --input day=2026-10-31` tries one run (signed in to a hub, it shows on the hub's Running page as `work-sales-etl`, live log and Stop included). Then `aihub work enable sales-etl && aihub work serve --bg` fires its triggers in the background, as the service `aihub-works` (log: `aihub run logs aihub-works -f`).

Only one process per machine fires cron and package triggers: this UI or `aihub work serve`, never both.

## Safety

127.0.0.1 only; random per-start key (cookie, HttpOnly, SameSite=Strict); Host/Origin checks; a custom header on every write; generated pages run in a sandbox with no network. Secrets from `settings.json`, `.env` files and the vault are never sent to the browser. Secrets you add under Settings are encrypted at rest (`~/.aihub/ui/secrets.bin`, key file mode 0600) and only reach the Claude process of a chat.

## Cache

The chat's system prompt (soul, note index, OpenUI rules) is built once and frozen, turns resume the same Claude session, and the page shows cache read/write per turn. Changing the model mid-chat or "Reload memory" rewrites the cache.

**Finding Claude Code**: the UI looks for `claude` on PATH, then in the usual install places (native installer `~/.local/bin`, npm / pnpm / bun / volta / nvm globals, Homebrew, the VS Code / Cursor extension's bundled binary); set `AIHUB_CLAUDE` to a full path to choose one. When none is found, a Claude Code chat is answered by AIHubness with your API key instead of failing (Works Claude nodes still report the error).

**Claude sign-in**: if `settings.json` has an `apiKeyHelper` that needs an OAuth sign-in, chats and Claude nodes check it first and offer Sign in. The key it prints is never stored or shown.

Every library ships in `ui/static/vendor/` (the lazy ones in `vendor/lazy/`, built by `python ui/tools/vendor_libs.py`), so the page works offline and loads nothing from a CDN. Map tiles still come from OpenStreetMap. HTML pages Claude writes in a chat may still use jsDelivr.
