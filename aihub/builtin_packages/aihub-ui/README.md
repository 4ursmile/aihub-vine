# aihub-ui

A local, Claude-style chat and control UI for AI Hub.

```sh
aihub install aihub-ui
aihub run aihub-ui          # background service; the address (with this session's key) is in ~/.aihub/ui/url.txt
```

- **Chat** with the Claude Code harness (`claude -p`): model picker (with the thinking-effort slider) and permission mode (Auto, Edit, Plan, Read, Bypass), engines Code (Claude Code), Lite (AIHubness) and Chat (Free chat), attachments, history in folders. Models, login, hooks, MCP servers, skills and agents all come from Claude's own `settings.json`, so everything `aihub install` registered is usable.
- **Answers render in place**: shell sessions, code, sortable tables, charts (`chart` blocks) and forms (`form` blocks, the submit goes back as your next message). Claude is told about them in the chat's frozen system prompt.
- **Context window**: a ring shows usage against the size set in Settings (default 1M tokens; also sent to Claude Code as `CLAUDE_CODE_AUTO_COMPACT_WINDOW`); Compact now, auto-compact and its limit. `/` opens slash commands: the UI's own, Claude Code's, and `slash/*.slash.json` from packages.
- **Live work card**: while Claude works you see the phase (reasoning / tools / answer), a step list with each tool and its result, the reasoning as it streams, counters (time, steps, estimated tokens, context) and two buttons: **Stop** and **Answer now** (stops the tools and asks for a short direct answer in the same session). Finished reasoning is a collapsible block.
- **Talk while it works** (Claude Code mode): a message typed during an answer goes straight into that answer; Claude reads it at its next step (after the current tool call), like typing into Claude Code while it works. It waits as a dashed chip until Claude has read it, then shows in the chat tagged "sent while Claude was working". **`/btw <question>`** asks a quick side question (also mid-answer): a throwaway fork of the chat answers it from the conversation in one step without tools; the answer is a dismissible card above the box and is not added to the chat. Free chat queues the message for when the answer ends.
- **Free chat**: the engine pill in the composer switches a chat to the UI's own harness: one streaming call to the Messages API, no Claude Code, no tools or files, fast and cheap. It needs `ANTHROPIC_API_KEY` (Settings > Encrypted secrets, or the `env` block / `apiKeyHelper` of your Claude settings; `ANTHROPIC_BASE_URL` is honoured; a subscription login only works through Claude Code). Switch at any message; earlier text carries over, tool calls do not. Free chat can use MCP servers: tick the ones you want in the engine pill (servers of installed aihub packages, the MCP servers page, and Claude Code's user servers; stdio only). The model then calls their tools in a loop (up to 12 rounds per message) and the calls show in the live card like Claude Code's. It draws an svg or writes an html report to the canvas only when you ask for one.
- **AIHubness** (engine pill, or `/engine aihub`): the UI's mini agent between Free chat and Claude Code. Same API key as Free chat, but with tools on the chat's working folder: `read`, `ls`, `grep`, `edit`, `write`, `run`, `digest`, `memory`. It loops (up to 40 rounds), retries failed steps and busy API calls, and keeps its own memory notes across chats (`~/.aihub/ui/harness/memory.md`). It is built for few tokens: about 1.7k tokens of fixed prompt (Claude Code: about 40k), a moving prompt-cache breakpoint, big files cut to their first lines plus an outline, unchanged re-reads skipped, long command output folded to head and tail with the full text saved for `grep` / `digest`, `digest` to send a big file to a small model with a question, old tool output trimmed in long tasks, and later messages get earlier ones as text plus a one-line list of steps. Commands ask like Claude Code: a card in the chat shows the command with Allow once / Always allow `<prefix>` (for this chat) / Deny, and the task waits (Stop ends it; no answer in 15 minutes = denied). Read-only commands (`ls`, `cat`, `rg`, `git status/diff/log`...) run without asking; Auto also runs test, build and lint commands, Accept edits asks for them; file edits in the working folder run. Deletes and discards (`rm`, `git clean`, `find -delete`, `git reset --hard`, removing a memory note...) and risky commands (`sudo`, `git push`, `kill`, `curl | sh`, publish) ask every time, never covered by Always allow. Bypass asks nothing. Plan / Read only = look only. Unattended Works runs refuse what would ask. Manage the memory notes (view, edit, add, delete) under Knowledge > AIHubness memory. Handoff chain: Free chat hands a task that needs files to AIHubness (on by default), and AIHubness hands one it cannot do to Claude Code (off by default). Both switches are in the engine pill and under Settings.
- **Working folder**: each chat works in `~/.aihub/workingspace/sessions/<id>` unless you pick a folder (folder chip in the chat header; a missing folder is created, the chat moves into a sidebar project of the same name, and new chats started in that project reuse it). Changing it starts a new Claude session that carries the conversation as text. **Soul**: the person button gives one chat its own soul text (or back to your soul note). **Search chats** in the sidebar looks in titles and messages.
- **Canvas**: a file tree of the working folder, live; Preview (Markdown files render like a chat answer: tables, code, charts, relative images), **Edit** (Ctrl/Cmd+S saves) and **Diff** (since your last message, or since the last git commit) tabs, and a split mode that shows the preview beside the editor or diff; `.html` files get a sandboxed live preview; Jupyter `.ipynb` notebooks open as cells you edit in place (add, move, retype, delete, clear outputs; Save writes the notebook, there is no kernel); `.drawio` files are drawn by draw.io's own viewer (loaded from www.draw.io, or from `ui/static/vendor/lazy/drawio/viewer-static.min.js` when you put it there for offline use), and by the built-in renderer when it cannot load; **VS Code** and **Open folder** (Finder / Explorer) buttons open the working folder or the selected file; `html`, `svg` and `openui` code blocks render under Elements. Components are [OpenUI](https://openui.com) (`@openuidev/react-lang` + `react-ui`), taught to Claude through the chat's frozen system prompt.
- **Packages**: installed list, find, install (options default on, then a settings form for keys), update, enable/disable, uninstall.
- **Services**, **MCP servers**, **Knowledge** (soul and notes = memory), **Works**: node graphs that start on a cron schedule, a webhook, a click or a package's own event source, with regex filters, Claude tasks (choose model / effort / mode) and package nodes. Mail: **Send email (SMTP)** (any server, any system; send, draft into the account's IMAP Drafts folder, or a `.eml` file) next to the Outlook package node (`aihub-nodes-outlook`, Windows; send, draft, display). **Saved nodes** (Works > Saved nodes): set a node up once, logins included (encrypted), then add it to any work from Add node > Saved nodes; empty fields follow it, typed ones change that work only. Data: **SQL database** (SQLAlchemy: PostgreSQL, SQL Server, Oracle, Trino, MySQL, SQLite, DuckDB; native, pandas or polars; writes tables), **Trino SQL** and **Spark job** nodes; node code reads the logins and S3 buckets it is granted through `aihub_vault`, databases through `aihub_data`. Code nodes have an **Environment** box (their Python, what is missing, one-click install or the one command), **Magic ask** (describe it, a model fills in the fields and code; Apply to keep) and a colour code editor that expands full screen to **Run** the node and preview its result. Headless runs: see "Works without the UI" below. Guide: `docs/ui-nodes.md`.
- **Settings** also holds the Vault (git logins), the hub sign-in (highlighted while you are signed out) and the context window.
- Same state as the terminal: it calls `aihub --json ...`, so login, vault and packages are shared.

## Renaming works and changing them from chat

- Rename a work from its row's ⋯ menu (or F2 on the row; `POST works/rename`), or click its name in the editor (pencil). Rename a node by double-clicking its title on the canvas or F2 on a selected node; right-click a node for Rename, Duplicate node, Disconnect all and Delete.
- A chat can change an existing work: it reads `~/.aihub/ui/works/<id>.json` and answers with a ```workflow block that keeps the work's `"id"`. The card lists what changes (renamed, added, removed, changed nodes and connections) and warns when the work is On; *Apply changes* updates it in place (nodes that keep their id keep their stored secrets, credential sets and saved node), *Undo* puts the previous version back (`POST works/restore`; the last 10 versions are kept in `ui/works-history/`). *Edit with chat* in the work's bar opens a new chat with the request started.

## Works without the UI

`aihub work` runs the same Works as this page from a terminal or a server, with no browser. It reads the same files, so a work designed here runs there, and the other way round. It needs this package (`aihub work` offers to install it). Every command is in `docs/cli.md`.

To run a shared workflow on a server:

1. `aihub install aihub-ui`.
2. `aihub work pull workflow-sales-etl` adds its works, switched off.
3. `aihub work setup sales-etl --creds creds.json --env data` sets its credential sets, folders and secret fields (or answer the prompts; `aihub work cred template s3` prints a skeleton), then installs the Python packages its SQL / Spark / Python nodes need into the environment `data`. Later or on its own: `aihub work env install sales-etl` (`aihub work env check sales-etl` lists them).
4. `aihub work run sales-etl --input day=2026-10-31` tries one run (signed in to a hub, it shows on the hub's Running page as `work-sales-etl`, live log and Stop included). Then `aihub work enable sales-etl && aihub work serve --bg` fires its triggers in the background, as the service `aihub-works` (log: `aihub run logs aihub-works -f`).

Only one process per machine fires cron and package triggers: this UI or `aihub work serve`, never both.

## Safety

127.0.0.1 only; random per-start key (cookie, HttpOnly, SameSite=Strict); Host/Origin checks; a custom header on every write; generated pages run in a sandbox with no network. Secrets from `settings.json`, `.env` files and the vault are never sent to the browser. Secrets you add under Settings are encrypted at rest (`~/.aihub/ui/secrets.bin`, key file mode 0600) and only reach the Claude process of a chat.

## Cache

The chat's system prompt (soul, note index, OpenUI rules) is built once and frozen, turns resume the same Claude session, and the page shows cache read/write per turn. Changing the model mid-chat or "Reload memory" rewrites the cache.

**Finding Claude Code**: the UI looks for `claude` on PATH, then in the usual install places (native installer `~/.local/bin`, npm / pnpm / bun / volta / nvm globals, Homebrew, the VS Code / Cursor extension's bundled binary); set `AIHUB_CLAUDE` to a full path to choose one. When none is found, a Claude Code chat is answered by AIHubness with your API key instead of failing (Works Claude nodes still report the error).

**Claude sign-in**: if `settings.json` has an `apiKeyHelper` that needs an OAuth sign-in, chats and Claude nodes check it first and offer Sign in. The key it prints is never stored or shown.

Every library ships in `ui/static/vendor/` (the lazy ones in `vendor/lazy/`, built by `python ui/tools/vendor_libs.py`), so the page works offline and loads nothing from a CDN. Map tiles still come from OpenStreetMap. HTML pages Claude writes in a chat may still use jsDelivr.

## Data Studio

`#/sql`: a lightweight SQL / MongoDB client in the browser. **Connections** are any SQLAlchemy database (PostgreSQL, MySQL, SQL Server, Oracle, Trino, SQLite, DuckDB, or a full URL) or MongoDB; passwords are kept in the encrypted secret box, never in the connections file or the browser. **Studio** has a schema tree, query tabs, history, a sortable result grid with CSV / JSON export, quick charts and column stats (see Notebook) and a read-only switch per connection. **Drivers** shows what each Python environment has and installs the extra package a database needs (also ClickHouse, Snowflake, BigQuery, Redshift, Databricks, ...) into the UI's Python or a managed environment. Queries run in a child Python of the connection's environment (`aihubui/sqlrunner.py`).

## Notebook

`#/notebook` (under Tools): Jupyter notebooks on a server you connect. **Servers** can be a JupyterHub (address, user, API token: your server is started when it is not running), any Jupyter Server / Lab (address + token), or **Local**: one click installs `jupyter_server` + `ipykernel` (+ pandas, matplotlib, numpy) into a managed environment and runs it on 127.0.0.1. Paste the address exactly as your browser shows it (`https://host/user/you/lab?token=…` is cleaned to `https://host/user/you`, the user and token are picked out; a missing `https://` is added). Setup screens (servers, connections) use the whole page. Tokens are encrypted on this machine and never reach the browser; every call goes through the UI.

- **Workspace**: file browser (new, rename, delete, upload), tabs, a notebook editor with a live kernel (run cell / all, interrupt, restart, switch kernel; the kernel survives a reload), outputs as real tables, figures and interactive HTML (plotly, bokeh in a sandboxed frame), and remote terminals (xterm.js) that open as tabs.
- **Upload by drop**: drop files or whole folders from your computer on the file list: on a folder row they go into that folder, elsewhere into the selected folder (the panel names the target while you drag). Existing names ask before they are overwritten; folders merge. Files over 6 MB go up in parts (Jupyter's chunked upload, up to 2 GB) with a progress bar and Stop. Drag a row onto a folder to move it.
- **Running** (rail button): like JupyterLab's *Running Terminals and Kernels*. Open tabs; every kernel on the server with its state, last activity and the notebooks attached (click to open), with Interrupt, Restart and Shut down (and Shut down all); terminals with open, new and shut down. Closing a terminal tab keeps the terminal running; shut it down here. A notebook whose kernel was shut down shows *Kernel offline · Reconnect*. API: `POST jupyter/running`, `POST jupyter/kernel/shutdown`; `jupyter/file/put` takes `chunk`.
- **Charts and stats on data**: a SQL cell's result and every pandas / polars DataFrame a cell prints get *Table · Charts · Stats* tabs (`static/dataviz.js`, the vendored ECharts; the same view is under Data Studio results). Charts: bar, stacked, horizontal, line, area, scatter / bubble with a trend line, pie, histogram, box plot, heatmap, treemap, several side by side, built from column pickers (aggregate, split by, date grouping, sort, top N); *Suggest* adds the ones that fit the columns. Stats: per-column type, missing, distinct, min / max / mean / median / std, top values, distribution, and a correlation matrix. The view is kept in the cell's `metadata.aihub.viz` (`sql` or the output index); a printed DataFrame charts only the rows it shows.
- **SQL cells**: pick *SQL* as the cell type, choose a Data Studio connection and optionally a variable: the rows are shown as a table and sent into the kernel as a pandas `DataFrame` (a list of dicts without pandas). Stored in the `.ipynb` as a code cell with `metadata.aihub.sql = {conn, var, limit}`.
- **AI help**, each with its own model (AI models tab, same list as the chat model picker): inline suggestions as ghost text (Tab accepts), *Ask AI* to write or change a cell (reviewed before it replaces anything; SQL cells use the database schema), *Fix with AI* on a failed cell.
- **As a node / from chat**: *Use as node* creates a work (Start manual with the notebook's `parameters` as inputs -> *Jupyter notebook* node). The node, the chat tool `notebook` and the CLI `aihubui/nbcli.py` run a notebook headless on a fresh kernel: parameters are set like papermill, SQL cells work, and the variable `result` is read back as JSON. Code: `aihubui/jupyter.py`, `jupyterai.py`, `wsclient.py`, `nodes/notebook_run.py`, `static/jupyter.js`.

### Sample data, MongoDB, Magic SQL modes and `@data:`

- **Sample data**: the first time Data Studio opens it adds a read-only SQLite connection, *Sample data (SQLite)* (`aihubui/sampledb.py`, a deterministic ~1 MB file at `~/.aihub/ui/sample.db`). Its tables are shaped for every chart type: `orders` / `daily_metrics` (time series, stacked bars), `web_traffic` (weekday x hour heatmap), `exam_scores` (histogram, box plot, scatter with trend), `products` (bubble), `employees` (treemap), `survey_responses`, `customers`, `events` (JSON column), two views, and `sample_guide` which says what each table is good for. Deleting it keeps it deleted; *Restore sample data* on the Connections tab brings it back.
- **Import a file**: *Import* in the Studio bar loads CSV / TSV / TXT, JSON (array of objects or arrays), JSON Lines or Excel `.xlsx` into a table (`static/sqlimport.js` parses it in the browser: delimiter sniffing, header row, sheet pick, inferred column types you can change, columns to skip). *New* creates the table, *Append* adds to an existing one (names must match), *Replace* drops and recreates it. Rows go to `POST sql/import` in chunks and are inserted through SQLAlchemy (`sqlrunner.import_rows`; MongoDB: `insert_many`). Read-only connections refuse it. The side panels of Data Studio and Notebook are resizable (drag the gap, double-click resets).
- **MongoDB** (`pymongo`, install it on the Drivers tab): host / port / user / password / database, or a `mongodb+srv://` connection string (kept in the secret box). Collections show in the schema tree with fields inferred from a sample (nested `a.b`). Statements are written like the mongo shell, `db.orders.find({status: "paid"}).sort({total: -1}).limit(20)`, `db.orders.aggregate([...])`, `countDocuments`, `distinct`, `show collections`, or the JSON form `{"collection": "orders", "find": {...}}`; `ObjectId()`, `ISODate()`, `/regex/i`, unquoted keys and single quotes are understood (`aihubui/mongorunner.py`). Documents come back as a flattened table, so Charts and Stats work as for SQL. Read-only connections allow find / aggregate / count / distinct only.
- **Magic SQL has two modes** (switch next to the button): *Fast* sends the schemas and writes once; *Agent* explores first, one read-only step at a time: it gets only the table names, then `tables` (filter by words), `describe` (columns of just the few tables it needs), `sample`, `values` (real distinct values to filter on) and `query`, and finally writes the statement, which is test-run before it is handed over. A failing step or query is shown to the model so it works around it. The steps are listed under the bar. Code: `sqlstudio.ask_agent`.
- **Chat: `@data:<connection>`** brings one data source into a message (menu: type `@`, pick *Data*). Only then does the message get the schema (small databases whole; for big ones the tables the message is about with columns, the rest by name), how to query it (Claude: `aihubui/sqlcli.py`; AIHubness: the `sql` tool; free chat: write a `sql` block) and how to draw (an `echarts` block with the real rows, or a `sql` block that opens in Data Studio). A chat that never mentions a data source carries none of this, and the AIHubness `sql` tool is not even offered.

### SQL files and parameters

In Data Studio, `:name` in a statement is a bind parameter (never pasted into the text; `::cast` and quoted text are left alone). A bar above the editor lists them with a value each. **Save** stores the query as a named SQL file (connection + parameter values as defaults). The **SQL file** work node (`db.sqlfile`, `nodes/sql_file.py`) runs a saved file and may override any parameter with a JSON object, e.g. `{"day": "{{data.day}}"}`; the *Jupyter notebook* node overrides notebook parameters the same way. API: `GET sql/files`, `POST sql/file/save|delete|run`. Database icons come from the public Simple Icons host and fall back to the name alone when it is unreachable.

### Notebook editing

- Cells have their own run button in the gutter. Changes are saved automatically about 1.5 s after the last edit (switch off in the status bar).
- Code intelligence: a completion list as you type, from names in the notebook and from the live kernel (DataFrame columns, methods, modules); Tab on a word opens it. No model tokens. AI inline suggestions (grey text) come on top, cached and with a compact context.
- The file list has folders and files in separate groups, a New menu (notebook, file, folder), Upload, and a path bar.
- Find and replace (Ctrl/⌘+F) across all cells with match case and regex; Contents panel lists text-cell headings; Run menu has "selected and below" and "all above".
- Settings (rail): switch the working server and set the AI help models without leaving the notebook. Servers are added or edited from "Add or edit servers".
- Data Studio and SQL cells complete keywords, tables and columns (aliases resolved) and show function signatures; Python cells show call signatures from the live kernel.
- Inline AI suggestions need token headroom: reasoning models think before answering, so an empty reply meant the budget ran out (fixed: 900 tokens for suggestions).
- Servers, SQL connections and Drivers are edited in place: a list on the left, a sectioned editor on the right with a sticky Save bar (no separate form page). The burger button no longer overlaps the page header.
- Code suggestions (Copilot style): fill-in-the-middle prompt with a line or block mode (a comment or a line ending in ":" asks for the next lines), live kernel variables (DataFrame columns and dtypes) as context, replies trimmed to the block, asked also before closing brackets. Alt+\ forces a suggestion.
- Data Studio uses the notebook layout (icon rail: Schema, Saved files, History, Settings), an always-visible Parameters bar with "Add parameter", and the Servers/Connections editors share the Settings-panel look.
- Suggestions: a syntax-tree engine (`codetree.py`) feeds imports, function signatures, classes, variables with inferred types and the enclosing function to the model; whole functions are suggested after a `def` line; replies are cached on disk (`suggest_cache.json`, 7 days) and a longer cached reply answers the same request a few letters later.
- Performance: output HTML is sanitised once and rendered outputs are reused while unchanged (a keystroke in a long notebook went from ~185 ms to ~16 ms), off-screen cells are skipped by the browser, SQL tabs are saved to storage 400 ms after typing stops.
- Speed (1.68): each cell is its own memoized component, so typing in a cell or output streaming into it re-renders that cell only; kernel output is folded in once per frame (a timer in a hidden tab), the Contents panel updates after a pause. The canvas notebook viewer no longer re-serializes the whole notebook on each key.
- Cleaner flow (1.68): the toolbar is Add / Run / Output on the left and Find, kernel, state, Save and a file menu (⋯) on the right; the cell's floating tools are type, move, ⋯ (the full cell menu) and delete; the run button replaces the `[n]` count on hover; Esc leaves a text cell.
- File actions everywhere: the ⋯ on a file row, on an open notebook or file, and right-click all open one menu: Save, Revert, Download (a notebook also as a `.py` in the percent format), Copy path, Copy full path (local servers), Copy name, Copy contents, Cut / Copy / Paste, Duplicate, Rename, Use as a Works node, Delete.
- Plain files (`.py`, `.sh`, SQL, text) in the Notebook page and in the chat canvas editor get the completion list (Ctrl+Space opens it) and AI grey text (Tab accepts, Alt+\ asks now; the canvas footer has Suggest on/off). Completion without a kernel is `POST code/complete` (`aihubui/codecomplete.py`): jedi when it is installed, else the file's names, keywords, builtins and members of the standard-library modules the file imports (modules with import side effects are never imported).
- Terminals (Notebook and chat): Ctrl/⌘+C copies a selection, Ctrl/⌘+V pastes, right click copies or pastes, ⌘K clears. Grey text after the cursor from that terminal's history, else (chat shell) the first completion, else after a pause from AI (→ accepts, Alt+→ one word, Esc hides); Ctrl+Space lists history and, in a chat shell, commands on PATH, git subcommands and the files and folders of the folder the shell is in now (it follows `cd`; `cd` lists folders only); a line starting with `# ` is a request and AI proposes the command. Colours follow the page theme.
- Chat canvas Edit tab: New file and New folder buttons in the file bar make them in the open file's folder (a name with `/` makes subfolders); with no file open the tab offers both.
- Chat terminal: leaving the chat detaches its shells instead of ending them; coming back (or reloading) re-attaches with the scrollback (`term/read?wait=0` probes; an unread shell lives 60 min). The tab's × ends a shell.
